## Why no fix was applied
The block is enforced at the platform classification layer (`await_phishing` / `trigger_indie` 409). It is:
- **Non-retryable** — a fresh `resume_pipeline` deterministically hits the same 409.
- **Not manifest-caused** — no build_image/health_check failure; the pipeline never reached those steps.
- **Not source/secret/tier/DNS** — nothing in the app's code or configuration changes this.

There is no deployer-agent tool that can lift an abuse/phishing block.
